5. STEP-BY-STEP SCENARIOS (PHARMACY PHASE - DESKTOP ONLY)
======================================================================
All testers will follow these scenarios sequentially to audit system status:

SCENARIO 1: ONBOARDING & SUPERADMIN APPROVAL
1. Pharmacy Owner Signup: A tester registers a new Pharmacy Owner, fills out brand info, and adds a physical branch (selecting coordinates on the Leaflet map).
2. Superadmin Verification: The Superadmin logs in, opens the branch review dashboard, verifies the coordinates on the review map, and approves the submission.
3. Status Check: The Owner receives the status update email (via Resend) and gains dashboard access.

SCENARIO 2: STAFF & INVENTORY MANAGEMENT
1. Branch Setup: The Branch Manager logs in and creates accounts for a Pharmacist and a Cashier.
2. Staff Verification: Pharmacist and Cashier log in with their temporary credentials and change their passwords.
3. Inventory Count: Staff audits active drug quantities.
4. Drug Transfer: The Manager requests a drug stock transfer from a sister branch. The sister branch manager accepts/rejects the transfer (verifying inventory decreases/increases in both databases).

SCENARIO 3: POS CASHIERING & CHECKOUT (DESKTOP ONLY)
1. Cashier Login: The Cashier opens the POS dashboard.
2. Order Placement: Cashier starts a walk-in transaction, selects drugs, and reviews checkout pricing.
3. Payment Methods:
   - CASH: Cashier enters amount received; the interface must calculate correct change.
   - CARD: Select card mock payment.
   - INSURANCE: Cashier enters patient insurance type (RSSB, MMI, etc.); the system must automatically apply correct copay/deductible coverage.
4. Fulfillment: Cashier completes order, downloads receipt PDF, and prints prescription sheet.

SCENARIO 4: CONCURRENCY CHECK (10-MINUTE RUSH)
* At exactly 01:45 PM, all testers (across both Hosted and Local tracks) will log in as Cashiers and process POS transactions simultaneously. The backend team will monitor logs (both locally and on Render) to verify database transactions complete successfully without deadlock errors.

6. NGORK DEVELOPMENT SETUP (FOR DEVELOPERS ONLY)
======================================================================
To connect the local frontend and local backend across remote machines:

FOR BACKEND DEVELOPERS:
1. Pull the backend branch "ft-ngrok-cors-fix" (or merge it into main).
2. Run your local backend: "npm run start:dev" on port 4000.
3. Open a separate terminal and run: "ngrok http 4000".
4. Copy the generated "https://xxxx.ngrok-free.app" URL and share it with the frontend team.

FOR FRONTEND DEVELOPERS:
1. Pull the frontend main branch.
2. Open your local "pharmacy_front/.env" file and set:
   NEXT_PUBLIC_API_URL=https://xxxx.ngrok-free.app/api
3. Restart your frontend server: "npm run dev".
4. Open the ngrok link once in your browser and click "Visit Site" to bypass the warning.
